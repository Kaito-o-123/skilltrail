# 04_詳細設計書.md

# 学習ロードマップ・スキル成長管理アプリ 詳細設計書

## 1. 目的

本設計書では、SkillTrailの実装コードをもとに、各機能の具体的な処理内容を定義する。  
URL、HTTPメソッド、View、Form、Model、入力チェック、DB操作、画面遷移、メッセージ、エラー時の動作を明確にし、実装内容と設計内容を一致させることを目的とする。

本書では、Django ORMを利用しているため、処理説明では主にModel名を使用する。物理テーブル名はDjango標準命名により `roadmap_category`、`roadmap_learninggoal`、`roadmap_roadmap`、`roadmap_learningtask`、`roadmap_reflection` となる。

## 2. 共通処理仕様

### 2.1 URL・View対応

| 機能 | URL | HTTPメソッド | View |
|---|---|---|---|
| ダッシュボード | `/` | GET | `dashboard` |
| 学習目標一覧 | `/goals/` | GET | `goal_list` |
| 学習目標登録 | `/goals/new/` | GET / POST | `goal_create` |
| 学習目標詳細 | `/goals/<pk>/` | GET | `goal_detail` |
| 学習目標編集 | `/goals/<pk>/edit/` | GET / POST | `goal_update` |
| 学習目標削除 | `/goals/<pk>/delete/` | GET / POST | `goal_delete` |
| ロードマップ登録 | `/goals/<goal_pk>/roadmaps/new/` | GET / POST | `roadmap_create` |
| ロードマップ編集 | `/roadmaps/<pk>/edit/` | GET / POST | `roadmap_update` |
| ロードマップ削除 | `/roadmaps/<pk>/delete/` | GET / POST | `roadmap_delete` |
| ロードマップ並び順変更 | `/roadmaps/<pk>/move/<direction>/` | GET | `roadmap_move` |
| タスク一覧 | `/tasks/` | GET | `task_list` |
| タスク登録 | `/tasks/new/` | GET / POST | `task_create` |
| タスク編集 | `/tasks/<pk>/edit/` | GET / POST | `task_update` |
| タスク削除 | `/tasks/<pk>/delete/` | GET / POST | `task_delete` |
| タスク完了 | `/tasks/<pk>/complete/` | POSTを想定 | `task_complete` |
| 振り返り一覧 | `/reflections/` | GET | `reflection_list` |
| 振り返り登録 | `/reflections/new/` | GET / POST | `reflection_create` |
| 振り返り編集 | `/reflections/<pk>/edit/` | GET / POST | `reflection_update` |
| 振り返り削除 | `/reflections/<pk>/delete/` | GET / POST | `reflection_delete` |

### 2.2 Form共通仕様

各ModelFormには `StyledFormMixin` を適用し、全フィールドのWidgetにCSSクラス `input` を付与する。  
フォーム送信時はDjango Formの `is_valid()` を利用してModelフィールドの必須・型・選択値チェックと、各Formで定義した追加チェックを実施する。

フォームが不正な場合は対象画面を再表示し、各フィールドのエラーとDjango Messagesによる `入力内容を確認してください。` を表示する。

### 2.3 メッセージ仕様

| 処理 | 成功メッセージ |
|---|---|
| 登録 | `登録しました。` |
| 更新 | `更新しました。` |
| 削除 | `削除しました。` |
| タスク完了 | `タスクを完了にしました。` |

メッセージはDjango Messages Frameworkを利用し、共通テンプレート `base.html` 上部に表示する。

### 2.4 対象データ未存在時

ID指定でデータを取得する処理は原則 `get_object_or_404()` を利用する。  
対象データが存在しない場合は個別メッセージ画面へ遷移せず、Django標準のHTTP 404応答となる。

### 2.5 DB例外

登録・更新・削除時に個別の `try-except` は実装していない。フォーム検証を通過した後のDB例外はDjangoの例外処理に委ねる。

## 3. ダッシュボード表示処理

### 3.1 処理概要

学習目標、タスク、振り返りを集計し、現在の学習状況をトップ画面に表示する。

### 3.2 使用View・Template

| 項目 | 内容 |
|---|---|
| View | `dashboard` |
| Template | `roadmap/dashboard.html` |
| HTTPメソッド | GET |

### 3.3 処理の流れ

1. `timezone.localdate()` で当日の日付を取得する。
2. `LearningGoal` をカテゴリ付きで取得する。
3. ステータスが `in_progress` の学習目標件数を集計する。
4. ステータスが `completed` の学習目標件数を集計する。
5. `completed` 以外の学習タスク件数を集計する。
6. 完了以外かつ期限設定済みで、期限が「当日 + 14日」以前のタスクを期限昇順で最大6件取得する。
7. 当月の `Reflection.study_time` を合計する。データがない場合は0分とする。
8. 振り返りを学習日降順・ID降順で最大3件取得する。
9. 完了以外の学習目標を更新日時降順で取得する。
10. 集計結果を `dashboard.html` に渡して表示する。

### 3.4 表示データ

| Contextキー | 内容 |
|---|---|
| `in_progress_count` | 学習中の目標数 |
| `completed_count` | 完了済み目標数 |
| `incomplete_tasks` | 未完了タスク数 |
| `month_minutes` | 当月の学習時間合計（分） |
| `upcoming_tasks` | 期限条件に一致する未完了タスク最大6件 |
| `recent_reflections` | 最近の振り返り最大3件 |
| `active_goals` | 完了以外の学習目標 |
| `today` | 当日日付 |

### 3.5 補足

「期限が近いタスク」は `due_date <= 当日 + 14日` で抽出しており、下限日付を指定していないため、期限超過タスクも対象に含まれる。

## 4. 学習目標一覧・検索処理

### 4.1 処理概要

登録済みの学習目標を一覧表示し、キーワード・カテゴリ・ステータスによる絞り込みを行う。

### 4.2 使用View・Template

| 項目 | 内容 |
|---|---|
| View | `goal_list` |
| Template | `roadmap/goal_list.html` |
| HTTPメソッド | GET |

### 4.3 検索条件

| GETパラメータ | 条件 |
|---|---|
| `kw` | `title` または `purpose` に部分一致（大文字小文字を区別しない） |
| `category` | `category_id` が一致 |
| `status` | `status` が一致 |

複数条件を指定した場合はAND条件として適用する。

### 4.4 処理の流れ

1. `LearningGoal` と関連Categoryを取得する。
2. GETパラメータ `kw` の前後空白を除去する。
3. `kw` が指定されている場合、タイトルまたは目的への部分一致検索を行う。
4. カテゴリが指定されている場合、カテゴリIDで絞り込む。
5. ステータスが指定されている場合、ステータスで絞り込む。
6. 作成日時降順で一覧表示する。
7. 検索条件を画面へ返し、入力状態を保持する。

### 4.5 DB操作

`LearningGoal` に対するSELECTのみ。検索結果をDBへ保存しない。

## 5. 学習目標詳細表示処理

### 5.1 処理概要

指定された学習目標の基本情報、進捗、ロードマップ、タスク、振り返り、学習時間合計を表示する。

### 5.2 使用View・Template

| 項目 | 内容 |
|---|---|
| View | `goal_detail` |
| Template | `roadmap/goal_detail.html` |
| HTTPメソッド | GET |

### 5.3 処理の流れ

1. URLの `pk` を使用して `LearningGoal` を取得する。Categoryは `select_related` で同時取得する。
2. 対象目標に紐づくRoadmapを取得し、各RoadmapのTaskを `prefetch_related` する。
3. 対象目標に紐づくReflectionを取得する。
4. `LearningGoal.progress_rate` により進捗率を算出する。
5. `completed_task_count`、`total_task_count` を表示する。
6. `total_study_minutes` により振り返りの学習時間を合計する。
7. 詳細画面を表示する。

### 5.4 データ未存在時

対象学習目標が存在しない場合はHTTP 404とする。

## 6. 学習目標登録処理

### 6.1 処理概要

ユーザーが入力した学習目標を登録する。

### 6.2 使用View・Form・Template

| 項目 | 内容 |
|---|---|
| View | `goal_create` |
| Form | `GoalForm` |
| Template | `roadmap/goal_form.html` |
| HTTPメソッド | GET / POST |

### 6.3 GET処理

1. 空の `GoalForm` を生成する。
2. 学習目標登録画面を表示する。

### 6.4 POST処理

1. POST値から `GoalForm` を生成する。
2. `form.is_valid()` で入力チェックを行う。
3. 正常な場合は `form.save(commit=False)` でLearningGoalインスタンスを生成する。
4. リクエストユーザーが認証済みの場合のみ `user` に設定する。
5. `goal.save()` を実行する。
6. `登録しました。` をsuccessメッセージとして設定する。
7. 学習目標一覧画面 `/goals/` へリダイレクトする。
8. 入力不正の場合は `入力内容を確認してください。` をerrorメッセージとして設定し、入力値を保持した登録画面を再表示する。

### 6.5 入力チェック

| 項目 | チェック内容 |
|---|---|
| タイトル | 必須、最大200文字 |
| カテゴリ | 必須、存在するCategoryを選択 |
| 目的 | 任意 |
| 開始日 | 任意、日付形式 |
| 目標期限 | 任意、日付形式。開始日と両方指定された場合は開始日以降 |
| ステータス | 必須、Modelで定義された選択値のみ |
| メモ | 任意 |

目標期限が開始日より前の場合、`目標期限は開始日以降の日付にしてください。` を目標期限フィールドに表示する。

### 6.6 DB操作

| 操作 | Model | 内容 |
|---|---|---|
| INSERT | `LearningGoal` | 入力された学習目標を登録 |

## 8. 学習目標削除処理

### 8.1 処理概要

学習目標を削除する。GET時は削除確認画面を表示し、POST時に削除を確定する。

### 8.2 使用View・Template

| 項目 | 内容 |
|---|---|
| View | `goal_delete` |
| Template | `roadmap/confirm_delete.html` |
| HTTPメソッド | GET / POST |

### 8.3 処理の流れ

1. URLの `pk` から対象LearningGoalを取得する。
2. GET時は削除確認画面を表示する。
3. 警告として `紐づくロードマップ・タスク・振り返りもすべて削除されます。` を表示する。
4. POST時に `delete()` を実行する。
5. `登録しました。` ではなく `削除しました。` を表示する。
6. 学習目標一覧画面へリダイレクトする。

### 8.4 関連データへの影響

- LearningGoal → Roadmap：`CASCADE`
- Roadmap → LearningTask：`CASCADE`
- LearningGoal → Reflection：`CASCADE`

そのため、学習目標削除時は配下のRoadmap、LearningTask、Reflectionも削除される。

## 12. ロードマップ並び順変更処理

### 12.1 処理概要

同一学習目標内のロードマップステップを1つ上または下へ移動する。

### 12.2 使用View

`roadmap_move(request, pk, direction)`

### 12.3 処理の流れ

1. `pk` から対象Roadmapを取得する。
2. 同じ学習目標に紐づくRoadmapを `sort_order`、`id` の順で取得する。
3. 対象Roadmapの現在位置を求める。
4. `direction == "up"` の場合は1つ前、それ以外は1つ後を交換対象とする。
5. 交換対象が存在する場合、2件の `sort_order` を入れ替える。
6. それぞれ `sort_order` のみUPDATEする。
7. 学習目標詳細画面へリダイレクトする。

先頭を上へ、末尾を下へ移動しようとした場合は更新を行わず、そのまま詳細画面へ戻る。

## 14. タスク登録処理

### 14.1 処理概要

ロードマップに紐づく学習タスクを登録する。画面上では学習目標を選択した後、その学習目標に紐づくロードマップを選択する。

### 14.2 使用View・Form・Template

| 項目 | 内容 |
|---|---|
| View | `task_create` |
| Form | `TaskForm` |
| Template | `roadmap/task_form.html` |
| HTTPメソッド | GET / POST |

### 14.3 初期表示

1. GETパラメータ `roadmap` が指定されている場合、対象Roadmapを取得し、そのRoadmapとLearningGoalを初期選択する。
2. `roadmap` がなく `goal` が指定されている場合、対象LearningGoalのみ初期選択する。
3. `next` が指定されている場合、戻り先として画面のhidden項目に保持する。

### 14.4 学習目標とロードマップの連動

`TaskForm` にはModel項目ではない `goal` フィールドを追加する。  
ロードマップのoptionには `RoadmapSelect` により `data-goal` 属性を設定し、画面JavaScriptで選択した学習目標に紐づくロードマップのみ表示する。

サーバー側でも `TaskForm.clean()` により、選択したRoadmapの `learning_goal_id` と選択したGoalのIDが一致することを確認する。不一致の場合は `選択した学習目標に紐づくロードマップを選択してください。` を表示する。

### 14.5 入力チェック

| 項目 | チェック内容 |
|---|---|
| 学習目標 | 必須 |
| ロードマップ | 必須、選択した学習目標に紐づくこと |
| タスク名 | 必須、最大200文字 |
| 教材URL | 任意、URL形式、最大500文字 |
| 優先度 | 必須、`high` / `medium` / `low` |
| 期限 | 任意、日付形式 |
| ステータス | 必須、`not_started` / `in_progress` / `completed` |
| メモ | 任意 |

### 14.6 POST処理

1. POST値から `TaskForm` を生成する。
2. 入力チェックを行う。
3. 正常な場合はLearningTaskを登録する。
4. `登録しました。` を表示する。
5. POSTされた `next` がある場合はそのURLへ、ない場合はタスク一覧へリダイレクトする。
6. 入力不正の場合は入力値とエラーを保持して画面を再表示する。

## 17. タスク完了処理

### 17.1 処理概要

対象タスクのステータスを `completed` に変更する。

### 17.2 処理の流れ

1. `pk` からLearningTaskを取得する。
2. `next` をPOST → GET → タスク一覧URLの優先順で決定する。
3. HTTPメソッドがPOSTの場合のみ `status` を `completed` に変更する。
4. `status` フィールドのみUPDATEする。
5. `タスクを完了にしました。` を表示する。
6. `next` の画面へリダイレクトする。

GETでアクセスされた場合はステータスを変更せず、戻り先へリダイレクトする。

### 17.3 進捗率への反映

タスク完了時に学習目標へ進捗率を保存する処理は行わない。  
画面表示時に `LearningGoal.progress_rate` が最新のタスク状態を参照して再計算するため、完了後の画面で自動的に最新値が表示される。

## 18. 進捗率算出処理

### 18.1 処理概要

LearningGoal配下の全LearningTaskに対して、完了件数の割合を算出する。

### 18.2 対象タスク

`LearningTask.objects.filter(roadmap__learning_goal=self)` により、対象LearningGoal配下の全Roadmapに紐づくタスクを取得する。

### 18.3 計算式

`round(完了タスク数 / 全タスク数 × 100)`

### 18.4 処理仕様

1. 全タスク数を取得する。
2. 全タスク数が0件の場合は0を返す。
3. `status == completed` のタスク数を取得する。
4. 完了数 ÷ 全件数 × 100を計算する。
5. Pythonの `round()` で整数に丸めて返す。

進捗率はDBカラムとして保持しない。

---

## 19. 学習時間集計処理

### 19.1 学習目標単位

`LearningGoal.total_study_minutes` で対象目標に紐づくReflectionの `study_time` をSUMする。NULLのみ、またはデータなしの場合は0分とする。

### 19.2 当月単位

ダッシュボードでは当年・当月のReflectionを対象に `study_time` をSUMする。データなしの場合は0分とする。

## 21. 振り返り登録処理

### 21.1 処理概要

学習内容、学習時間、課題、次回行動をReflectionとして登録する。

### 21.2 使用View・Form・Template

| 項目 | 内容 |
|---|---|
| View | `reflection_create` |
| Form | `ReflectionForm` |
| Template | `roadmap/reflection_form.html` |
| HTTPメソッド | GET / POST |

### 21.3 GET処理

1. 学習日の初期値として当日を設定する。
2. GETパラメータ `goal` が指定されている場合、学習目標を初期選択する。
3. GETパラメータ `next` を戻り先として保持する。
4. 振り返り登録画面を表示する。

### 21.4 入力チェック

| 項目 | チェック内容 |
|---|---|
| 学習目標 | 必須 |
| 学習日 | 必須、日付形式 |
| 学習時間 | 任意、0以上の整数 |
| 学んだこと | 必須 |
| 詰まったこと | 任意 |
| 次にやること | 任意 |

### 21.5 POST処理

1. POST値から `ReflectionForm` を生成する。
2. 入力チェックを行う。
3. 正常な場合はReflectionを登録する。
4. `登録しました。` を表示する。
5. POSTされた `next` があればその画面へ、なければ振り返り一覧画面へリダイレクトする。
6. 入力不正の場合は入力内容を保持して登録画面を再表示する。

## 22. 振り返り更新処理

### 22.1 処理概要

登録済みReflectionを編集する。

### 22.2 処理の流れ

1. `pk` からReflectionを取得する。
2. `next` をPOST → GET → 振り返り一覧URLの優先順で決定する。
3. GET時は既存値を設定した `ReflectionForm` を表示する。
4. POST時に入力チェックを行う。
5. 正常な場合は更新し、`更新しました。` を表示する。
6. `next` の画面へリダイレクトする。
7. 入力不正の場合は編集画面を再表示する。

---

## 23. 振り返り削除処理

### 23.1 処理概要

Reflectionを削除する。

### 23.2 処理の流れ

1. `pk` からReflectionを取得する。
2. `next` をPOST → GET → 振り返り一覧URLの優先順で決定する。
3. GET時に削除確認画面を表示する。
4. POST時に削除する。
5. `削除しました。` を表示する。
6. `next` の画面へリダイレクトする。

## 25. 削除制御

| 親Model | 子Model | on_delete | 動作 |
|---|---|---|---|
| User | LearningGoal | CASCADE | ユーザー削除時に学習目標も削除 |
| Category | LearningGoal | PROTECT | 学習目標から参照中のカテゴリ削除を禁止 |
| LearningGoal | Roadmap | CASCADE | 学習目標削除時にロードマップも削除 |
| Roadmap | LearningTask | CASCADE | ロードマップ削除時にタスクも削除 |
| LearningGoal | Reflection | CASCADE | 学習目標削除時に振り返りも削除 |

LearningGoalの `user` は初期実装では `null=True`、`blank=True` のため、未ログイン状態で登録した学習目標はユーザー未設定を許容する。

## 29. 実装対象外・現行仕様上の境界

現行実装では、以下は機能として実装していない。

- カテゴリを画面から登録・編集・削除する機能
- ログイン必須化およびユーザー単位の一覧絞り込み
- 学習目標の期限による一覧絞り込み
- タスクの期限による一覧絞り込み
- 振り返りのキーワード・学習日による絞り込み
- ロードマップ単位の独立した進捗率保存
- タスク完了状態を未完了へ戻す専用ボタン
- 進捗率のDB保存
