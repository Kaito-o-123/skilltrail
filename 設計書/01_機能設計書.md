# 学習ロードマップ・スキル成長管理アプリ 機能設計書

## 1. 目的

本設計書では、学習ロードマップ・スキル成長管理アプリ「SkillTrail」が提供する機能を、現在の実装内容に基づいて整理する。各機能の目的、利用者操作、入力・出力、機能間の関連を明確にし、画面設計・DB設計・詳細設計との整合性を確保する。

## 2. アプリケーション概要

SkillTrailは、学習したい技術やスキルを「学習目標」として登録し、目標達成までのロードマップ、具体的な学習タスク、進捗率、日々の振り返りを一元管理するWebアプリケーションである。

利用者は「何を学ぶか」だけでなく、「どの順番で学ぶか」「次に何をするか」「どこまで完了したか」「何を学んだか」を継続的に記録・確認できる。

### 2.1 管理対象

- 学習カテゴリ
- 学習目標
- ロードマップステップ
- 学習タスク
- 振り返り
- タスク完了状況から算出する進捗率
- 振り返りに記録した学習時間

### 2.2 初期実装の前提

- DjangoによるWebアプリケーションとして提供する。
- DBはDjango ORMを通して操作する。
- 認証機能は初期実装の主要対象外とし、未ログイン状態でも学習目標を登録できる。
- ログイン済みの場合のみ、登録した学習目標にユーザー情報を紐づける。
- 進捗率はDBに保持せず、関連タスクの状態から表示時に算出する。

## 4. ダッシュボード表示機能

### 4.1 目的

アプリケーション起動時に、現在の学習状況を一画面で把握できるようにする。

### 4.2 表示情報

| 表示項目 | 内容 |
|---|---|
| 学習中の目標数 | `status = in_progress` の学習目標件数 |
| 完了済み目標数 | `status = completed` の学習目標件数 |
| 未完了タスク数 | `completed` 以外のタスク件数 |
| 今月の学習時間 | 当月の振り返り `study_time` の合計 |
| 学習目標ごとの進捗 | 完了済みを除く学習目標と進捗率 |
| 期限が近いタスク | 未完了かつ期限が本日から14日以内のタスクを期限順に最大6件表示 |
| 最近の振り返り | 学習日の新しい順に最大3件表示 |

### 4.3 利用者操作

- 新規学習目標登録画面へ遷移する。
- 学習目標を選択して詳細画面へ遷移する。
- 学習目標一覧画面へ遷移する。
- 振り返り登録画面へ遷移する。

## 5. 学習目標管理機能

### 5.1 概要

学習したい技術・スキルを学習目標として管理する。学習目標はロードマップ、タスク、振り返りの起点となる。

### 5.2 登録・編集項目

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | ○ | 学習目標名。最大200文字 |
| カテゴリ | ○ | 登録済みカテゴリから選択 |
| 目的 | - | 学習する理由・到達したい状態 |
| 開始日 | - | 学習開始日 |
| 目標期限 | - | 完了予定日 |
| ステータス | ○ | 未着手、学習中、完了、中断 |
| メモ | - | 補足情報 |

### 5.3 入力制御

- タイトルとカテゴリは必須とする。
- 開始日・目標期限は日付形式とする。
- 開始日と目標期限の両方が入力されている場合、目標期限は開始日以降でなければならない。
- ステータスは定義済みの選択肢のみ許可する。

### 5.4 一覧・検索

学習目標一覧では次の条件を組み合わせて絞り込む。

| 条件 | 検索対象 |
|---|---|
| キーワード | タイトル、目的の部分一致 |
| カテゴリ | `category_id` の完全一致 |
| ステータス | `status` の完全一致 |

※期限による絞り込みは現行実装には含まれない。

### 5.5 詳細表示

学習目標詳細では次を表示する。

- 基本情報（カテゴリ、タイトル、目的、メモ、ステータス、開始日、目標期限）
- 学習時間合計
- 全タスク数、完了タスク数、進捗率
- 紐づくロードマップステップと各ステップのタスク
- 紐づく振り返り

### 5.6 削除

学習目標削除時は確認画面を表示する。削除確定時、Djangoの外部キー設定により、紐づくロードマップ、ロードマップ配下のタスク、振り返りも連鎖削除される。

## 6. ロードマップ管理機能

### 6.1 概要

学習目標を達成するまでの学習ステップを順序付きで管理する。

### 6.2 登録・編集項目

| 項目 | 必須 | 内容 |
|---|---|---|
| ステップ名 | ○ | 学習ステップ名。最大200文字 |
| 説明 | - | ステップで学習する内容 |
| 並び順 | ○ | 1以上の整数 |
| ステータス | ○ | 未着手、進行中、完了 |

### 6.3 登録時の初期値

新規ステップ登録画面を開いた場合、並び順の初期値は「対象学習目標に登録済みのロードマップ件数 + 1」とする。

### 6.4 並び順変更

学習目標詳細画面からステップを上または下へ移動できる。同じ学習目標に属するステップを `sort_order`, `id` の順で並べ、移動対象と隣接するステップの `sort_order` を入れ替える。先頭で上移動、末尾で下移動を行った場合は変更しない。

### 6.5 削除

ロードマップステップ削除時は確認画面を表示する。削除確定時、紐づくタスクも連鎖削除される。

## 7. 学習タスク管理機能

### 7.1 概要

ロードマップステップを実行可能な具体的作業単位へ分解し、期限・優先度・状態・教材URL等を管理する。

### 7.2 登録・編集項目

| 項目 | 必須 | 内容 |
|---|---|---|
| 学習目標 | ○ | タスク登録フォーム上でロードマップ候補を絞り込むための選択項目 |
| ロードマップ | ○ | 実際にタスクが紐づくロードマップ |
| タスク名 | ○ | 実施内容。最大200文字 |
| 教材URL | - | 教材・参考資料URL。最大500文字 |
| 優先度 | ○ | 高、中、低 |
| 期限 | - | 完了予定日 |
| ステータス | ○ | 未着手、進行中、完了 |
| メモ | - | 補足情報 |

※「学習目標」は `LearningTask` テーブルに直接保存する項目ではない。選択されたロードマップから学習目標を特定する。

### 7.3 入力制御

- ロードマップ、タスク名、優先度、ステータスは必須とする。
- 教材URLはURL形式とする。
- 学習目標とロードマップの所属関係をサーバー側でも検証し、不一致の場合は登録・更新しない。
- 画面側では学習目標の選択に応じてロードマップ候補を絞り込む。

### 7.4 一覧・検索

| 条件 | 検索対象 |
|---|---|
| キーワード | タスク名、メモの部分一致 |
| 学習目標 | ロードマップ経由の学習目標ID |
| ステータス | `status` の完全一致 |
| 優先度 | `priority` の完全一致 |

※期限条件による検索は現行実装には含まれない。

### 7.5 タスク完了

未完了タスクに対して完了操作を行うと、`status` を `completed` に更新する。進捗率そのものをDBへ保存する処理は行わない。画面再表示時に学習目標の進捗率を再算出する。

### 7.6 期限超過判定

期限が未設定または完了済みの場合は期限超過としない。それ以外で `due_date < 当日` の場合に期限超過として画面表示上識別する。

## 8. 進捗管理機能

### 8.1 算出単位

学習目標単位で、その目標に属する全ロードマップ配下のタスクを集計する。

### 8.2 算出式

`進捗率 = round(完了タスク数 / 全タスク数 × 100)`

- タスク0件の場合は0%とする。
- 完了判定は `LearningTask.status = completed` とする。
- 算出結果はDBへ保存せず、必要時に算出する。

## 9. 振り返り管理機能

### 9.1 概要

学習日ごとの学習内容、所要時間、詰まった点、次回の行動を記録する。

### 9.2 登録・編集項目

| 項目 | 必須 | 内容 |
|---|---|---|
| 学習目標 | ○ | 紐づく学習目標 |
| 学習日 | ○ | 学習した日 |
| 学習時間（分） | - | 0以上の整数 |
| 学んだこと | ○ | 学習内容 |
| 詰まったこと | - | 課題・不明点 |
| 次にやること | - | 次回予定 |

### 9.3 登録時初期値

新規登録時、学習日の初期値を当日とする。学習目標詳細等から `goal` パラメータが指定された場合は対象学習目標を初期選択する。

### 9.4 一覧・絞り込み

振り返り一覧は学習日の降順、同日の場合はID降順で表示する。現行実装の絞り込み条件は学習目標のみである。

### 9.5 学習時間集計

- 学習目標詳細：対象学習目標に紐づく全振り返りの `study_time` 合計。
- ダッシュボード：当月の全振り返りの `study_time` 合計。
- 未入力の学習時間は集計上0として扱う。

## 10. 画面復帰制御（nextパラメータ）

タスクおよび振り返りの登録・編集・削除では、呼び出し元へ戻るため `next` パラメータを利用する。`next` が指定されていない場合は、それぞれタスク一覧または振り返り一覧を既定の遷移先とする。

## 11. 共通機能

### 11.1 メッセージ表示

Django Messages Frameworkを利用し、登録・更新・削除・完了の成功時に完了メッセージを表示する。フォームエラー時は「入力内容を確認してください。」を表示し、各フィールドの詳細エラーもフォーム上に表示する。

### 11.2 データ未存在時

URLで指定された学習目標、ロードマップ、タスク、振り返りが存在しない場合、`get_object_or_404` によりHTTP 404とする。

### 11.3 共通ナビゲーション

サイドバーからダッシュボード、学習目標、タスク、振り返りの各一覧へ遷移できる。

## 12. 現行実装対象外・将来拡張

現行コードには次の機能は含まれていないため、初期実装の機能範囲外とする。

- ログイン必須化およびユーザー単位の完全なデータ分離
- カテゴリの画面上での登録・編集・削除
- 学習目標の期限条件検索
- タスクの期限条件検索
- 振り返りのキーワード・学習日検索
- ロードマップ単位の独立した進捗率算出
- グラフ・チャートによる高度な可視化
- 通知・リマインド機能
